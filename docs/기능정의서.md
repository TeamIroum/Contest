# 시니어 동네 점검단 기능정의서 v1.0

작성일: 2026-10-10. 개발 기준: API 명세 v1.0(기존 v0.2 수정본), DB 설계 v1.1, 서비스 설계서, AI 연동 계약. 기능의 구현 완료를 나타내는 문서는 아니다.

## 1. 목적과 범위

2인 1조의 시니어가 지정 코스의 시설 외관을 촬영하고, 담당자가 사진을 검토해 보수와 재점검·수리 확인까지 관리한다. 대상은 보도블록·빗물받이·벤치·안전펜스·운동기구다. 시설을 열거나 만지거나 작동 시험하는 일은 참여자 업무에 포함하지 않는다.

기능별 우선순위 P0는 2026-10-15 핵심 시연, P1은 후속 업무 연결, P2는 확장·운영 관리다. 이는 기존 구현 순서를 기능 단위로 정리한 작업 우선순위이며 실제 완료 여부와 다르다. ‘연동대기’는 해당 외부 계약·구현 확인 전 활성화하지 않는 기능, ‘상세정의 필요’는 목적은 정해졌지만 API·운영값이 부족한 기능이다. 나머지는 현재 문서에 근거한 개발 기준이다.

AI 실제 호출·기기 마스킹·오프라인은 각각 구현 증거를 확인한다. 시연에 검증된 사진이나 모의 AI를 사용하면 화면·발표에서 실제 기능과 구분한다.

## 2. 사용자와 권한

| 사용자 | 역할 코드 | 담당 기능 | 접근 범위 |
|---|---|---|---|
| 참여자 | SENIOR | 오늘 순회, 촬영, 건너뛰기, 쉬기, 복귀 요청 | 본인이 배정된 순회·공동 진행 |
| 활동 담당자 | ACTIVITY_MANAGER | 참여자·조·코스·일정, 출결·출발·복귀, 재점검 배정 | 담당 수행기관·거점 |
| 시설 담당자 | FACILITY_MANAGER | 시설 대장, 사진 판정, 사건·보수·수리 확인 | 담당 부서·시설 관할 |
| 사업 총괄 | PROGRAM_MANAGER | 기관·역할·정책, 전체 실적 | 승인된 사업·기관 범위 |
| 시스템 | — | 저장·상태 갱신·동기화·작업 복구·감사 | 요청자의 권한과 업무 규칙 안에서 수행 |

계정 하나에 여러 역할을 부여할 수 있다. 활동 담당자 역할만으로 시설 판정 권한이 생기지 않는다. 시연 관리자에게 여러 역할을 부여하는 것은 시연 계정 정책이다. 시니어 두 명은 별도 계정이며 누구든 사진을 제출할 수 있다.

| FAC-06 | 증거 연결·해제 | 사건·사진·사유·version | 사진↔사건 다대다 연결과 해제 이력 저장 | 해제해도 과거 감사 기록 보존 | P1 · 해제 요청 세부 형식 정의 필요 |
| FAC-07 | 보수 요청·시작·완료 | 부서·보수 내용·완료 시각·승인 증거 | 보수 이력 기록. 완료 이벤트·사건 확인 대기·재점검 요청 함께 저장 | 실제 부서 외부 시스템/업체 앱 연계는 범위 밖 | P1 |
| FAC-08 | 확인 근거 준비 | 현재 요청·보수 이벤트·확인 방법·증거 | PHOTO는 유효한 전후 사진, SITE_VISIT는 현장 근거로 확인 초안 생성 | 과거 회차·다른 시설·잘못된 AFTER 증거 거절 | P1 |
| FAC-09 | 수리 최종 확인 | 확인 ID·CLOSE/REPAIR_AGAIN/FOLLOW_UP_REQUIRED·사유·버전 | 현재 보수 회차에서 사람 판단으로 종결/재보수/추가 확인 | AI close_case 자동 실행 금지. 오래된 요청은 STALE_VERIFICATION | P1 |
| FAC-10 | 개인정보 사진 검토 | media·ok·사유·version | 실패 사진 즉시 접근 차단, 승인 참조 해제·재검토·보류 전달 | ok=true만으로 거절 사진 재승인하지 않음 | P1 · 사후 보류 전파 연동대기 |
| FAC-11 | 참고·보수 증거 업로드 | 목적·소유 범위·마스킹 사진 | 개인정보 단독 검사 후 승인 자료 저장 | 해당 검사 연결 전 업로드 비활성화. 시연 사전 검사 자료 사용 | P1 · 연동대기 |

추가 확인과 수리 확인은 다음 정기 순회 또는 담당자의 별도 현장 확인으로 처리한다. 시니어의 당일 재방문·코스 이탈을 요구하지 않는다. 작업자·업체의 보수 결과는 시설 담당자가 기록한다.

## 9. 핵심 상태와 완료 조건

| 구분 | 상태/판정 | 의미 |
|---|---|---|
| 활동 | ASSIGNED→IN_PROGRESS→RETURNING→COMPLETED | 담당자 출발 후 활동, 두 명 복귀 확인 후 정상 완료 |
| 중도 활동 | RETURNING(returnReason=ABORT)→ABORTED | 중도 복귀 후 두 명 확인. 출발 전 취소는 CANCELLED |
| 장소 | PENDING/CAPTURED/SKIPPED/REVIEW_REQUESTED/NOT_VISITED | 채택·건너뛰기·검토 인계·미방문을 서로 구분 |
| 사진 접수 | RECEIVING/RECEIVED/NO_MEDIA/RETRY_REQUIRED | 예약/영속 사진 보관/사진 없는 실패/사진 재전송 필요 |
| 사진 처리 | PROCESSING/ACCEPTED/RETAKE_REQUIRED/TECHNICAL_FAILED/REVIEW_REQUESTED | 접수 여부와 별개인 처리 결과 |
| 사건 | OPEN→REPAIR_REQUESTED→IN_REPAIR→AWAITING_VERIFICATION→CLOSED | 보수 완료 보고만으로 종결하지 않음 |
| 수리 판단 | CLOSE/REPAIR_AGAIN/FOLLOW_UP_REQUIRED | 사람의 종결/재보수/추가 확인 판단 |

하나의 구도에는 현재 채택 사진 하나만 존재한다. 모든 필수 구도가 채택되거나 검토 인계되면 다음 장소로 진행한다. 품질 재촬영 실패와 서버 기술 실패를 서로 다른 이유로 기록한다.

## 10. 수용 기준

| 검수 ID | 관련 기능 | 확인 시나리오와 합격 기준 |
|---|---|---|
| ACC-01 | COM-01, SEN-01 | 다른 조의 순회 ID로 조회·제출할 수 없다. 미배정은 빈 목록으로 표시한다 |
| ACC-02 | ACT-06, ACT-07 | 한 명 결석/참여 중지 시 출발 거절. 두 명 정상이며 시간 중복이 없을 때만 출발한다 |
| ACC-03 | SYN-02, COM-06 | 두 계정이 같은 구도에 동시에 제출해도 중복 시도/채택이 생기지 않고 대기 사진을 성급히 삭제하지 않는다 |
| ACC-04 | SEN-04, SEN-05 | 사진 없는 retake도 실패 이력을 남긴다. 총 세 번 품질 실패 후 검토 인계하며 기술 실패는 횟수에서 제외한다 |
| ACC-05 | SEN-06, FAC-02 | 한 장소의 필수 구도에 검토 인계가 포함되어도 진행하고 해당 실패 작업을 관리자에게 표시한다 |
| ACC-06 | SYN-04, SYN-05 | 오프라인 영속 저장 성공 후 진행, 재연결 시 같은 ID로 복구. 저장 실패나 업로드 시간 초과를 성공으로 표시하지 않는다 |
| ACC-07 | ACT-09, SEN-10 | 사진 대기가 있어도 두 사람 복귀 확인 후 활동 완료. 이후 사진 처리 결과가 활동을 다시 열지 않는다 |
| ACC-08 | SEN-03, FAC-03 | 기기 원본이 외부로 전송되지 않으며 미승인/거절 사진은 조회·시설 판독에 쓰지 않는다 |
| ACC-09 | FAC-07, SYS-03 | 보수 완료 도중 오류 발생 시 이벤트·사건 상태·요청·outbox가 모두 롤백한다 |
| ACC-10 | FAC-08, FAC-09 | 과거 회차/다른 시설 증거로 종결하지 못하며 동시 CLOSE/REPAIR_AGAIN 중 한 판정만 확정한다 |
| ACC-11 | FAC-04, SYS-02 | AI의 후속 결과가 사람 판정을 덮어쓰지 않고 시니어 화면에 위험도·이상 근거를 표시하지 않는다 |
| ACC-12 | OPS-03, OPS-04 | 한 명이 모든 사진을 제출해도 두 사람의 출결을 별도 집계하고 보고 문장의 수치가 DB 집계와 일치한다 |

부분 DB 검증은 14개 테이블과 참고 트랜잭션의 회귀 검사 29개가 통과했다. 이는 위 전체 기능/API/화면의 검수 완료가 아니다. 권한·기기 마스킹·오프라인·증거 자격·전체 DDL·실제 Spring/JPA는 별도 검수한다.

## 11. 보류 항목과 적용 범위 밖

| 항목 | 남은 결정·조건 |
|---|---|
| 인증 | 토큰 만료·MFA 방식·SMS 제한·번호 변경/재할당 절차 |
| 현장 운영 | 코스 거리·시설별 장수·인력 배치·활동시간 인정·보험·기상 중단·긴급 대응 |
| 사진·오프라인 | 최대 해상도·보관/삭제 기한·동기화 기한·초과 접수·브라우저 실기기 검증 |
| AI | 실제 fixtures·오류 코드·멱등 처리·사진 버전/보류 전파·개인정보 단독 처리·보고 스키마 |
| 관리 API | 역할 부여/철회, 프로그램 정책, 번호 변경 후속 처리 등 아직 상세 경로가 없는 기능 |

공개 신고·공개 회원가입, 참여자의 보수 작업, 상시 이동 경로 추적, 자동 코스 최적화, AI 자동 사건 종결, 실제 보수 부서 시스템 연계는 현재 기능 범위에 포함하지 않는다. 운영 정책 관리 화면을 이 문서만으로 신규 확정한 것으로 해석하지 않는다.
