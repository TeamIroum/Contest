# 시니어 앱 실제 촬영 기능 적용 요청

2026-10-12 · 요청: AI 담당 → 프론트엔드 담당

시니어 앱(`frontend/senior`)의 촬영·전송 화면을 지금의 시연용 흉내에서 실제 동작으로 바꿔 주세요. 카메라, 흐림 확인, 얼굴·번호판 가리기, 대기함은 시험용 PWA(`tools/ai-verify/pwa`)에서 아이폰 실기기로 확인을 마친 코드가 있으니 옮겨 쓰면 됩니다. **화면 디자인과 흐름은 지금 그대로 둡니다.** 바꾸는 것은 `Camera`·`Upload`·`afterUpload` 안쪽 동작뿐입니다.

## 1. 할 일

| 시니어 앱 (`frontend/senior/src`) | 지금 | 바꿀 내용 | 참고할 코드 (`tools/ai-verify/pwa`) |
|---|---|---|---|
| `App.tsx`의 `Camera` | 시설 그림(`Photo`)을 보여 줌 | 그림 자리에 `<video>`로 후면 카메라 화면을 띄움. 네모 틀·안내 문구·지난 사진 겹쳐 보기는 그대로 위에 겹침 | `camera.js`의 `open`, `close` |
| `App.tsx`의 `shoot()` | 촬영음만 내고 `upload` 화면으로 감 | `camera.capture` 한 번으로 촬영음 → 약 0.3초 동안 5장면 중 가장 선명한 것 → 흐림·어두움 확인 → 가리기 → 보낼 JPEG 재확인까지 끝남. 결과를 대기함에 넣고 전송 | `camera.js`의 `capture` (아래 사용 예) |
| 흐림·어두움 확인 | 없음 (시연용 버튼으로 흉내) | `camera.capture`가 `{ ok: false, reason }`을 돌려주면 올리지 않고 바로 `Retake` 화면으로 (문구는 `camera.RETAKE_TEXT[reason]`). 서버와 같은 계산(선명도 60, 밝기 45 기준). 서버에 가지 않았으므로 재촬영 횟수에 넣지 않음 | `camera.js`가 `quality.js`를 부름 |
| `App.tsx`의 `Upload` | 진행 막대를 시간으로 채움 | 실제 단계에 맞춰 문구를 바꿈: 가리는 중 → 보내는 중 → 결과 확인 중. 끝나면 서버 답으로 다음 화면을 정함 | `app.js`의 `submit`, `handleResponse` |
| `App.tsx`의 `afterUpload()` | `blurNext`·`stop.blurCount`로 실패를 정함 | 서버 답(2장 표)으로 정함. 재촬영 횟수도 서버가 주는 `retakesRemaining`을 씀 | `app.js`의 `handleResponse` |
| 시연용 "흔들린 사진으로 찍기" 버튼 | 있음 | 삭제 | — |
| 장소·구도 목록 (`data.ts`) | 예시 데이터 | 업무 API의 오늘 순회로 바꿈 (3장) | `app.js`의 `fetchPatrol`, `applyPatrol` |
| 끝난 장소 | 다시 찍을 수 있음 | 이미 끝난 구도(`ACCEPTED`, `REVIEW_REQUESTED`)는 찍기 버튼을 끄고, 모두 끝났으면 "오늘 순회를 모두 마쳤어요"를 보여 줌 | `app.js`의 `isResolved`, `openPatrol`, `showStop` |
| 대기함 | 없음 | 가린 사진을 IndexedDB에 먼저 저장한 뒤 보냄. 연결되면 자동으로 다시 보냄. 홈 화면에 "전송 대기 N" 표시 | `outbox.js` |

### `camera.js` 사용 예

`camera.js`는 화면과 상관없이 `<video>` 요소만 받습니다. React에서는 이렇게 부르면 됩니다.

```tsx
import * as camera from './camera/camera.js'
import * as masking from './masking/masking.js'
import * as outbox from './offline/outbox.js'

// 앱 시작 때 한 번: 가림 모델 받기 (처음 약 20MB). 끝나기 전에는 찍기 버튼을 끔
outbox.configure({ dbName: 'senior-outbox' })   // 대기함 이름 (처음 쓰기 전에 한 번)
await masking.loadModels(() => {}, { manifestUrl: '/models/model-manifest.json' })   // 실패하면 다시 시도. masking.ready()로 확인

// '도착했어요 · 사진 찍기' 버튼: 클릭 처리 안에서 소리를 준비해야 아이폰이 촬영음을 낸다
onClick={() => { camera.unlockSound(); setScreen('camera') }}

// Camera 화면
const video = useRef<HTMLVideoElement>(null)
useEffect(() => {
  camera.open(video.current!).catch((e) => showError(e.message))   // e.reason: 'denied' | 'unavailable'
  return () => camera.close(video.current!)
}, [])
<video ref={video} playsInline muted />

// 셔터 버튼 (클릭 처리 안에서 바로 부름)
async function shoot() {
  const r = await camera.capture(video.current!, {
    appVersion: APP_VERSION,
    onShutter: flashScreen,                    // 촬영음 직후. 화면을 한 번 번쩍임
    onProcessing: () => setScreen('upload'),   // '가리는 중' 화면. 카메라는 이미 닫힘
  })
  if (!r) return                                         // 카메라 영상이 아직 없음
  if (!r.ok) return showRetake(camera.RETAKE_TEXT[r.reason])   // 흐림·어두움·가리기 실패. 서버로 보내지 않음
  const item = {
    clientSubmissionId: crypto.randomUUID(), attemptId: crypto.randomUUID(),
    patrolId, stopId, stopName, captureSlotId,
    capturedAt: r.capturedAt, maskingVersion: r.maskingVersion, deviceMaskReport: r.report, blob: r.blob,
  }
  await outbox.put(item)                                   // 먼저 기기에 저장 (가린 사진만)
  const res = await outbox.send(item, { apiBase })         // { done, http, body, offline }
  afterUpload(res)                                         // 2장 표대로 다음 화면
}
```

`r.info`에는 고른 장면·선명도·처리 시간·가린 위치가 들어 있습니다(사진 내용은 없음). 시험 기록이 필요할 때만 씁니다.

## 2. 서버 답에 따른 화면

전송 결과는 업무 API `POST /patrols/{id}/stops/{stopId}/inspections`의 답으로 정합니다.

| 서버 답 | 보여 줄 화면 | 비고 |
|---|---|---|
| `nextAction: "RETAKE"` | `Retake` (문구는 서버 `message`) | 흐림·어두움·대상이 틀 밖 |
| `nextAction: "NEXT_STOP"` 또는 `"NEXT_CAPTURE"` | `Sent` → 다음 구도/장소 | `nextStopId`가 있으면 그 장소로 |
| `nextAction: "RETURN_TO_CENTER"` | `Sent` → `Return` | 마지막 장소 |
| `captureStatus: "REVIEW_REQUESTED"` | `Sent`의 "담당자가 확인할게요" (`outcome = 'review'`) | 재촬영 3번째 실패, 또는 AI가 시설을 알아보지 못한 사진 |
| `code: "SLOT_RESOLVED"` (409) | "이미 끝난 곳이에요" → 다음 장소 | 대기함에서 지움 |
| 연결 안 됨, 5xx, `code: "SUBMISSION_PROCESSING"` | "전송 대기 · 연결되면 자동으로 보낼게요" → 다음 장소로 가도 됨 | 대기함에 남김. **성공으로 안내하지 않음** |
| 그 밖의 4xx | "보내지 못했어요. 담당자에게 알려 주세요" | 대기함에 남기되 자동 재전송 안 함 |

위험도·판독 결과는 서버가 보내지 않으며, 화면에도 띄우지 않습니다.

## 3. 옮길 파일과 쓸 API

**옮길 파일** — React와 상관없는 코드라 거의 그대로 씁니다. `camera.js`가 `../masking/masking.js`를 부르도록 import 경로만 맞춰 주세요.

**타입 선언 파일도 함께 옮겨 주세요.** `camera.d.ts`, `masking.d.ts`, `outbox.d.ts`, `quality.d.ts`를 같은 이름의 `.js` 옆에 두면 `tsconfig.json`을 바꾸지 않고(`allowJs` 없이) strict 타입 검사와 자동 완성이 됩니다. `camera.d.ts`와 `outbox.d.ts` 안의 `./masking.js` import도 옮긴 위치에 맞춰 고쳐 주세요. 시니어 앱과 같은 `tsconfig.json`으로 위 사용 예를 `tsc`로 검사해 통과를 확인했습니다.

| 시험용 PWA 파일 | 시니어 앱 위치 (제안) | 내용 |
|---|---|---|
| `pwa/masking.js` | `src/masking/masking.js` | 얼굴(YuNet)·번호판(t-384)·차량(EfficientDet) 검출과 가리기, JPEG 만들기 |
| `pwa/download.js` | `src/masking/download.js` | 모델 파일 받기(진행률·이어 받기·재시도) |
| `pwa/camera.js` | `src/camera/camera.js` | 카메라 열기·닫기, 촬영음, 연속 촬영, 흐림 확인, 가리기 호출 (위 사용 예) |
| `pwa/quality.js` | `src/camera/quality.js` | 흐림·어두움 계산 (`camera.js`가 씀) |
| `pwa/outbox.js` | `src/offline/outbox.js` | IndexedDB 대기함, 전송, 자동 재전송 |
| `ai/contract/yunet_web/yunet.mjs` | `src/masking/yunet.mjs` | 얼굴 검출 전후처리. `masking.js`는 `./lib/yunet.mjs`로 불러오므로 위치를 옮기면 import 경로를 고침 |
| 모델 파일 | `public/models/` | `face_yunet_s_dynamic@1.onnx`(`ai/contract/yunet_web/`), `plate-t384@1.onnx`, `efficientdet_lite0@1.tflite`(`tools/ai-verify/pwa/models/`). 이름에 버전이 붙어 있음 |

**옮긴 파일은 고치지 말고 그대로 써 주세요.** 그래야 AI 쪽에서 기준(번호판 점수 등)을 고쳤을 때 파일만 다시 복사하면 됩니다. 시니어 앱에 맞출 것은 모두 옵션으로 넘깁니다.

| 맞출 것 | 방법 |
|---|---|
| 모델 위치 | 모델 3개를 `public/models/`에 두고 `python tools/ai-verify/pwa/make_model_manifest.py frontend/senior/public/models`를 실행하면 `model-manifest.json`이 생깁니다. 앱에서는 `masking.loadModels(onChange, { manifestUrl: '/models/model-manifest.json' })`. 모델 파일을 바꾸면 스크립트를 다시 실행합니다 |
| 모델 주소를 직접 넘길 때 | `loadModels(onChange, { models: { face, plate, vehicle } })`. 주소마다 `?v=<내용 해시>`가 있어야 합니다. 해시가 없으면 받지 않습니다(같은 주소의 예전 모델을 캐시에서 계속 쓰게 되므로) |
| 검출 라이브러리 | 기본은 jsDelivr CDN(`onnxruntime-web@1.20.1`, `@mediapipe/tasks-vision@0.10.14`). 직접 올려 둘 때는 `{ ortUrl, mediapipeUrl }`로 폴더 주소를 넘깁니다 |
| 대기함 이름 | `outbox.configure({ dbName: 'senior-outbox' })` (기본 `pwa-test-outbox`) |

위 방식은 시니어 앱과 같은 폴더 구성(`/models/`, `/src/masking/`, `/src/camera/`)을 만들어 브라우저에서 확인했습니다. 목록으로 받기·주소 직접 넘기기 모두 모델을 받아 번호판을 가렸고, 해시 없는 주소는 거절했습니다.

**쓸 API** — 시험용 업무 API(검증 콘솔, `http://127.0.0.1:8100/api/v1`)가 [API 명세서](API_명세서.md) 6·7절 형식으로 응답합니다. `.env`의 `VITE_API_ORIGIN`에 넣어 연결합니다.

| 요청 | 쓰는 곳 |
|---|---|
| `GET /me/patrols` | 오늘 순회 찾기 |
| `GET /patrols/{patrolId}` | 장소·구도 목록과 구도별 상태(`captureStatus`, `retakesRemaining`) |
| `POST /patrols/{patrolId}/stops/{stopId}/inspections` | 가린 사진 전송 (multipart: `file`, `clientSubmissionId`, `captureSlotId`, `attemptId`, `capturedAt`, `maskingVersion`, `deviceMasked=true`, `deviceMaskReport`) |
| `POST /patrols/{patrolId}/test-reset` | 시험용: 구도 상태 초기화 (실제 API에는 없음) |

`clientSubmissionId`는 다시 보낼 때 그대로 써야 서버가 같은 사진을 두 번 접수하지 않습니다. 새로 찍으면 새 ID를 만듭니다.

## 4. 꼭 지킬 것

- **원본은 어디에도 남기지 않습니다.** 원본 캔버스는 가린 뒤 바로 크기 0으로 지웁니다. IndexedDB·캐시·서비스 워커에는 가린 사진만 넣습니다.
- **가리지 못하면 보내지 않습니다.** 모델을 못 불러왔거나 가리기 중 오류가 나면 사진을 버리고 "한 번 더 찍어 주세요"를 띄웁니다. 모델이 준비되기 전에는 찍기 버튼을 끕니다.
- `deviceMaskReport`에 가린 위치(`boxes`, 0~1 비율)를 함께 보냅니다. 서버가 앱이 놓친 수(`server_added`)를 셀 때 씁니다.
- 갤러리에서 사진 고르기, `<input type="file" capture>`는 쓰지 않습니다. 앱 안 카메라로만 찍습니다.
- 카메라는 HTTPS에서만 열립니다. 개발 중 휴대폰 시험은 Tailscale Funnel 주소로 합니다(`tools/start-test.ps1` 참고).

자세한 기준: [앱 마스킹 구현 안내서](../ai/contract/APP_MASKING_GUIDE.md), [시니어 앱 README "꼭 지킬 것"](../frontend/senior/README.md)

## 5. 확인 방법

- [ ] 아이폰 사파리와 안드로이드 크롬에서 후면 카메라가 앱 안에 열린다
- [ ] 찍으면 촬영음이 나고, 찍은 사진이 휴대폰 갤러리에 저장되지 않는다
- [ ] 흔들리게 찍으면 올리지 않고 바로 다시 찍기 화면이 나온다
- [ ] 사람 얼굴과 차 번호판이 가려진 사진만 서버에 도착한다 (검증 콘솔 기록에서 확인)
- [ ] 비행기 모드에서 찍으면 "전송 대기"가 되고, 연결되면 자동으로 접수된다
- [ ] 같은 구도에서 품질 실패가 3번 나면 "담당자가 확인할게요"로 다음 장소로 넘어간다
- [ ] 이미 끝난 장소는 찍기 버튼이 꺼져 있고, 모두 끝나면 "오늘 순회를 모두 마쳤어요"가 나온다
- [ ] 위험도·판독 결과가 어르신 화면에 나오지 않는다

## 6. 참고: 시험에서 확인한 것 (아이폰, 2026-10-12)

| 항목 | 값 |
|---|---|
| 가리기 처리 시간 | 약 0.45~0.68초 (얼굴 0.2초, 번호판 0.12초, 차량 0.12초) |
| 보내는 사진 | 882×1568, 약 300~430KB |
| 서버·AI 처리 | 약 3.8초 |
| LTE에서 올리는 시간 | 4~13초로 들쭉날쭉 (Wi-Fi에서는 1~2초) |
| 번호판 기준 | 0.6점 이상만 가림. 번호판 없는 사진 86장 거짓 검출 0장, 한국 차 사진 속 번호판 25개 중 24개 가림 (`ai/eval/privacy/device_plate_threshold.py`) |

- 아이폰은 가리기 계산 중 1~3초 화면이 멈춥니다. 셔터 효과(화면 번쩍임)를 먼저 그린 뒤 계산을 시작해야 어르신이 찍혔다고 느낍니다(`app.js`의 `afterPaint`).
- LTE에서는 전송이 오래 걸리므로 `Upload` 화면에 "보내는 중"을 분명히 보여 주세요.
- 아이폰에서 홈 화면에 추가해 실행하면 카메라 권한을 다시 물을 수 있습니다.
