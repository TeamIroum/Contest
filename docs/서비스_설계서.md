# 시니어 동네 점검단 서비스 설계서 v1.0

정리일: 2026-10-10. 대화에서 확정한 서비스 방향을 통합했다. 이전 가이드·운영안과 충돌하면 이 문서를 우선한다. 단, AI 관련 내용은 [AI_기능_설계.md](AI_기능_설계.md)를 우선한다(2026-10-11 결정). 실제 기관 승인·운영 검증을 마친 기준은 아니다.

2026-10-11 갱신: AI 관련 기준 문서와 AI 계약 v2.0 내용을 반영했다.

후속 결정 반영: DB는 PostgreSQL로 확정했다. 배포 순서는 로컬 Docker → EC2 첫 배포 → GitHub Actions 자동화다. 인증·업무 API는 [API_명세서.md](API_명세서.md) v1.0, 저장 구조는 [DB_설계.md](DB_설계.md)를 기준으로 한다. 제공 AI의 /verify를 비교 지원으로 연결할 수 있으나 최종 종결·재보수는 사람이 결정한다. 실제 시연 포함 여부는 기능 설정으로 구분한다. AI 기능 범위와 역할 분담은 [AI_기능_설계.md](AI_기능_설계.md), AI 호출 형식은 [AI 판독 API 계약서 v2.0](../ai/contract/API_CONTRACT.md)를 따른다. [AI_연동_계약.md](AI_연동_계약.md)는 v2.0 이전 문서이므로 다르면 위 두 문서를 따른다.

## 목적과 대상

환경정비와 병행하지 않는 시설점검 전담 활동이다. 보도블록·빗물받이·공원 벤치·안전펜스·운동기구의 외관을 촬영한다. 참여자는 시설을 만지거나 열거나 수리하거나 직접 작동 시험하지 않는다. 사진상 이상 미발견은 시설 안전 보장이 아니다.

## 운영 주체

| 역할 | 업무 |
|---|---|
| 사업 총괄 | 사업·기관·부서 관리, 예산·협의, 전체 실적 확인 |
| 활동 담당자 | 참여자 교육, 조·코스 배정, 출결·안전·출발·복귀, 재촬영 일정 반영 |
| 시설 담당자 | 사진·AI 결과 검토, 이상 판정, 보수 요청·처리 기록, 수리 확인·종결 |

행정복지센터는 집결 거점이다. 활동 담당자는 수행기관 직원일 수 있으며 센터 사용·인력 배치는 협의가 필요하다. 보수 작업자·업체가 작업하고 결과를 전달하면 시설 담당자가 시스템에 기록한다. 시설 배정은 시설 대장에 등록된 관리 부서를 우선한다. 공모전은 관리자 계정 하나에 세 역할을 부여한다.

## 참여자와 순회

- 각자 개인 휴대폰·계정으로 로그인한다. 관리자가 참여자를 등록한다. 실제 운영은 등록 휴대폰 SMS 인증 방향이며 공모전 SMS 구현은 제외한다. 시연용 사전 생성 계정을 사용하고 인증 상세는 별도 설계한다.
- 활동 시간·생활권·걷는 속도를 고려해 2인 1조를 편성하고, 인원이 홀수면 한 조만 3인 1조로 한다. 결원 시 재편성하고 대체자가 없으면 활동을 보류한다.
- 사전 확인한 고정 코스를 배정한다. 공통 실습을 진행하고 필요한 조만 개별 동행한다.
- 말로 촬영 담당을 정하되 앱에는 지정·교대 절차나 촬영 권한 제한을 두지 않는다. 조원 누구든 촬영하고 실제 제출자를 기록한다.
- 같은 순회의 장소·진행률을 공유한다. 출석은 어르신이 앱에서 요청하고 담당자가 한 사람씩 확인해 확정한다. 로그인만으로 출석 처리하지 않는다.
- 조 대표는 앱 기록·연락, 동료는 장소·누락·주변 확인을 맡으며 교대 가능하다. 안전 책임을 조 대표에게 전담시키지 않는다.

### 하루 3시간 시험 운영 초안

집결·출석·컨디션·안내 15분 → 이동 15분 → 점검 45분 → 휴식 15분 → 점검 60분 → 복귀·인원 확인·마무리 30분.

시간 배분은 시험 후 조정한다. 필요 시 추가 휴식하며 시간 채우기용 추가 시설을 강제 배정하지 않는다. 활동시간 인정은 수행기관 확인 사항이다.

담당자는 매 활동일 출발 전·복귀 후 조원을 각각 확인하고, 활동 중 연락에 대응하며 예정 복귀 지연 시 전화 확인한다. 주 1회 일부 구역을 순차 방문한다. 새 코스·도움 요청·반복 누락 조는 추가 확인한다. 조 수 확대 시 담당 인력을 함께 검토한다.

## 시니어 앱

오늘 순회 → 앱 출석 요청·담당자 확인 → 담당자 출발 확인 → 어르신 활동 시작 → 장소 안내 → 촬영·저장·업로드 → 다음 장소 자동 안내 → 반복 → 센터 복귀 → 담당자의 조원별 복귀 확인 → 활동 완료.

- 장소 참고 사진·큰 글씨·간단한 방향을 먼저 보여주고 지도는 필요할 때 연다.
- AI의 이상 여부·위험도·판독 근거는 시니어에게 표시하지 않는다. 사진 품질에 따른 재촬영만 안내한다.
- 담당자 전화·쉬기·중도 종료를 제공한다.
- 촬영 불가 사유는 입력 없이 `위험해서 못 찍겠어요 / 장소를 못 찾겠어요 / 시설이 없어졌어요 / 다른 이유로 못 찍겠어요` 중 선택한다. 시설이 없어졌으면 시설 담당자가 시설 대장을 확인한다. 저장 후 다음 장소를 안내한다.
- 사진 품질 문제는 최초 촬영 + 재촬영 최대 2회(총 3회)까지 시도한다. 계속 실패하면 담당자 확인 요청을 남기고 다음 장소로 자동 진행한다. 위험하거나 촬영 불가인 경우 횟수를 채울 필요 없이 사유 선택으로 건너뛴다.
- 인터넷·서버 문제는 재촬영 횟수에 포함하지 않는다. 저장 가능한 사진은 기기에 보관했다가 앱을 다시 열거나 연결이 돌아오면 전송한다(백그라운드 자동 전송은 보장하지 않음, [API_명세서.md](API_명세서.md)). AI 서버가 꺼진 시간이면 다음 활동 시간에 전송된다. 기술적 재전송 횟수·간격은 구현 정책으로 별도 설정한다.
- 촬영 또는 건너뛰기 사유가 모두 기록되면 순회를 종료하고 복귀를 안내한다.
- 전송·분석·담당자 검토 대기가 있어도 복귀 확인 후 오늘 활동은 완료된다.
- 중도 종료는 담당자에게 연락하고 함께 복귀한다. 남은 장소는 중도 종료로 미방문 기록한다.

## 촬영 기준

시설별 참고 구도와 장수를 미리 지정하고 사용자가 장수를 고르거나 이상을 판단하게 하지 않는다. 최종 장수는 현장·AI 검증 후 확정한다.

- 보도블록·빗물받이·벤치: 지정 구간/시설 전체 1장부터 시험.
- 안전펜스: 긴 펜스를 짧은 점검 구간으로 나누어 구간당 1장부터 시험.
- 운동기구: 전체 1장부터 시험하고 가려진 부분이 있으면 정해진 다른 방향 사진을 추가하도록 설계.
- 수리 확인은 이전 마스킹 사진을 촬영 화면에 겹쳐 구도를 맞추도록 지원.

## 개인정보·AI·오프라인

- 목표: 기기 내 얼굴·번호판 마스킹 후 전송, 서버 재검사·추가 마스킹 후 판독·조회. 원본 외부 전송 금지는 실제 검증이 필요한 구현 요구다.
- AI가 맡는 일과 담당 범위는 [AI_기능_설계.md](AI_기능_설계.md)의 네 기능(개인정보 마스킹, 시설·이상 판독, 전후 비교, 보고 문장)과 역할 분담을 따른다.
- 서버 검사 후 AI가 사진을 다시 가리거나 보류하면 업무 저장본과 관리자 조회에도 반영한다(AI 계약 v2.0의 `GET /events`). 참고 사진·보수 증거는 판독 없이 개인정보 검사만 거친다(`/privacy/mask`).
- 사진 품질은 두 단계로 확인한다. 흐림·어두움은 AI 호출 전에 코드가 1초 안에 판단하고, 대상이 틀 밖이거나 시설이 안 보이는 경우만 AI가 판단한다. 어르신이 현장에 있을 때 재촬영을 안내해야 하므로 판독은 모아서 하지 않고 사진이 올라오면 바로 한다.
- 판독 AI는 처음부터 공개 모델을 자체 서버에 올려 운영한다. 사진을 외부 AI API로 보내지 않는다. 비용은 활동 시간에만 GPU 서버를 켜서 줄인다([AI_실행_가이드.md](AI_실행_가이드.md) 4.6절).
- 관리자 표시: `확인 필요 · 보도블록 들뜸 의심`과 사진·근거. AI 위험도 등급은 어느 화면에도 표시하지 않고 판정·알림·우선순위에 쓰지 않는다(2026-10-11 결정).
- 숫자는 서버가 집계하고 AI는 확정 수치로 보고 문장을 작성한다. 사진 제출 수와 개인 참여 실적을 구분한다.
- 순회 전에 코스·참고 사진·안내를 다운로드한다. 오프라인은 마스킹 사진을 기기에 저장하고 다음 장소로 진행한다. 앱을 다시 열거나 연결이 돌아오면 전송하며, 그 전까지 서버 분석은 대기 상태로 둔다.
- 저장 실패를 성공으로 안내하지 않는다. 마스킹 실패 시 원본 전송으로 우회하지 않는다.
- A의 사진이 대기 중 B가 같은 순회 장소를 접수하면, A는 재연결 시 접수 확인 후 중복 제출 없이 정리하고 진행률을 맞춘다. 서버도 동시 요청을 중복 집계하지 않는다.
- 접수 경쟁 단위는 순회 장소의 촬영 구도 ID이며, 시도는 clientSubmissionId/attemptId로 구분한다. 구도별 총 3회 품질 실패 한도와 미접수 상대 폰 대기 사진 활용은 v1.0 계약에 정리했다.

## 관리자 판정과 검토 범위

| 판정 | 후속 처리 |
|---|---|
| 이상 확인 | 보수·조치 대상으로 등록 |
| 이상 미발견 | 사유를 남기고 검토 종료 |
| 추가 확인 필요 | 다음 정기 순회 재촬영 또는 별도 현장 확인 |

- 확인 필요·반복 촬영 실패·수리 확인 재촬영은 전부 검토한다.
- 사진상 이상 미발견은 표본 검토한다. 비율은 시범 운영 후 조정한다.
- 활동일마다 정해진 시간에 모아서 검토한다. 시니어는 검토를 기다리거나 당일 다시 돌아가지 않는다.
- 긴급 대응 체계와 검토 지연 대응은 실제 운영기관과 별도 협의한다. 위 검토 일정이 즉각 위험 대응을 대체하지 않는다.

## 보수와 수리 확인

이상 확인 → 담당 부서 보수 요청 → 처리 완료 보고 → 다음 정기 순회 재촬영 → AI 비교·시설 담당자 최종 확인 → 종결 또는 재요청/추가 확인.

추가 사진·수리 확인은 다음 정기 순회에 반영한다. 기다리기 어려운 위험 의심은 시설 담당자가 별도 현장 확인한다. 시니어의 당일 재방문·코스 이탈을 요구하지 않는다.

같은 시설의 같은 미해결 문제는 기존 건에 사진·날짜를 추가한다. 다른 문제 또는 종결 후 재발은 새 건으로 만들고 과거 이력을 연결한다. 잘못된 연결은 시설 담당자가 수정할 수 있다. 공모전은 실제 부서 시스템 연계 없이 보수 요청·완료를 관리자 화면에 기록한다.

## 남은 결정

1. 시설별 복수 구도 촬영에서 품질 재촬영 횟수 적용 단위, 기술적 재전송 간격·횟수와 지속 실패 처리.
2. 코스별 거리·시설 수·최종 촬영 장수·담당자당 조 수: 현장 시험.
3. 사진·임시 데이터 보관·삭제, 권한, 마스킹 실패 상세 처리.
4. 오프라인 충돌·복구, 사전 다운로드 실패, 품질 불량 접수와 대기 사진 처리.
5. Java/Spring Boot 버전·DB·빌드 도구, 실제 실행 서버와 Cloudflare 사용 제품.
6. 2026-10-15 시연 기능별 실제 구현/모의 시연 범위. SMS는 제외 확정.
7. 기관 협의: 집결 장소·활동시간 인정·보험·사고·기상 중단·긴급 대응 체계.
