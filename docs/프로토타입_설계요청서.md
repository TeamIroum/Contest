# 요청: 「양주 생활 접근성 지도」 프로토타입 설계서 작성

## 배경
- 2026 양주시 미래인재 AI 공모전(팀 이로움) 본선 결과물의 설계서 작성. 이번 요청은 설계서까지이며, 구현은 10.10에 따로 요청
- 첨부: 이로움_기획안.pdf(제출한 기획안), access-report.html(1차 분석 리포트). 첨부가 빠졌으면 기획안 범위와 디자인 기준을 추측하지 말고 확인이 필요하다고 표시할 것
- 1차 분석에 쓴 원본 데이터와 코드가 함께 첨부되면, 새로 수집하거나 다시 만들지 말고 그대로 재사용
- 기획안 범위를 지키고, 바꿀 곳은 이유와 함께 먼저 제안
- 기획안은 이미 제출했고 시상은 기획안(1차)과 본선 점수를 합산하므로, 기획안과 달라지는 곳은 빠짐없이 설계서의 "기획안 대비 변경점" 표에 적을 것
- 화면과 문서는 모두 한국어로 작성
- 표의 짧은 칸(이름·날짜·구분 등)에는 화면에서 줄이 나뉘지 않도록 보이지 않는 문자(U+2060 단어 결합 문자, U+00A0 줄바꿈 없는 공백)를 넣었음. 이 칸의 이름·날짜·용어를 파일·폴더 이름, AI_LOG.md, 설정값, 코드로 옮길 때는 이 문자를 빼고 쓸 것

## 진행 방식
1단계: 설계서(Markdown)와 AI_LOG.md 초안을 작성하고 멈출 것
- 설계서는 아래 순서로 구성
  1. 지금 바로 수집을 시작할 데이터 목록과 받는 방법: 항목별로 승인 필요 여부와 예상 소요 기간을 적고, 승인이 걸리는 항목을 맨 위에 둘 것(10.9 한글날과 10.10~11 주말에는 기관 승인이 처리되지 않을 수 있음)
  2. 멘토링용 한 쪽 요약: 제작 범위, 역할 분담, 기능별로 AI가 만든 것과 팀이 정하고 검증한 것
  3. 본문: 항목별로 핵심만 간결하게
  4. 부록: 데이터 받는 방법 세부, 함수 입력·출력 형식, 선택지 비교표 등
- 본문에 담을 것
  - 화면 구성(담당자 분석 화면 / 시민 조회 화면), 데이터 흐름, 폴더 구조, 파일·함수 목록, 일정
  - 데이터 확보가 불확실한 항목과 대안
  - 배포 파일 크기와 브라우저 계산 속도 예상치
  - LLM 무료 사용량으로 시연·심사 기간을 버틸 수 있는지 예상치(심사 기간과 예상 사용자·질문 수 가정을 밝힐 것. 보고서 초안 호출과, 정제 보조를 API로 돌리면서 키를 나누지 않으면 그 호출도 포함)
  - 팀이 정해야 할 항목(아래 "미정 항목")별 선택지 비교와 추천안
  - 기획안 대비 변경점: 기획안의 기능·AI 활용 방안·실행 계획 중 이번 구현에서 빼거나 미루거나 바꾼 것을 표로(기획안 문구 / 이번 구현 / 이유 / 발표에서 설명할 말). 본선 질의응답 대비용. 최소한 다음을 넣을 것: 가. "보고서 초안 생성" → 템플릿 보고서(1순위)와 LLM 문장(2순위, 자리표시자) 나. "조건이 빠지면 다시 질문" → 화면 설정값으로 채우고 지명·지점이 모두 없을 때만 다시 질문 다. ②의 "심야 시간대 우선" → 전체 약국 운영시간으로 20시·22시 등을 계산(공공심야약국만 남기면 공백이 과장됨) 라. 실행 계획 "10.5~10.15 구현" → 10.9 멘토링 뒤 10.10 구현 시작 마. "날짜·시간 선택" → 요일·시각과 공휴일 구분값 바. 차별점: 격자 크기 대신 야간 운영시간·후보 비교·느린 보행·자연어 질의 사. "자동 갱신 구조" → 재실행 갱신 스크립트 아. 야간진료 기관은 2순위 자. 시민 화면은 3순위(빠지면 확장 계획으로 설명)
- 무료 한도, 격자 크기, 라이선스, 속도 근거, 국가 기준처럼 바뀌거나 틀리기 쉬운 사실에는 출처 링크와 확인일을 달고, 확인하지 못한 것은 "미확인"으로 표시할 것
- 이 요청서 곳곳에 있는 "설계서에서 제안·확정할 것" 항목도 빠짐없이 다루고, 설계서 끝에 "요청 항목 → 설계서 위치" 대응표를 붙일 것

2단계: 10.9 멘토링 피드백을 설계서에 반영한 뒤, 10.10부터 구현 시작
- 10.9 멘토링에서 제작 범위·역할 분담·AI 활용을 점검받으므로, 설계서는 그 판단에 필요한 내용을 담을 것
- 10.9까지는 구현 코드를 만들지 말 것. 단, 데이터 수집·정제와 학습용 실험 코드(경로 계산 사전 실험, LLM 호출 실험 등)는 예외
- 구현 기간이 6일(10.10~10.15)뿐이므로, 설계서에 기능별 우선순위와 "시간이 부족할 때 뺄 기능"을 명시할 것

## 구현 범위와 우선순위
1. **① 격자 접근성 지도:** 격자별로(격자 크기는 아래 데이터 항목 참고) 약국·의원·소아 진료기관과 어린이집·학교·공원까지 도보·차량 추정시간. 일반 보행과 느린 보행(0.7m/s. 경찰청의 교통약자 횡단 보행속도 기준을 이동 전체에 적용한 가정) 모드(시설별 순서는 아래 구현 우선순위 참고). 시설별로 어떤 인구를 셀지와 느린 보행의 적용 대상은 "미정 항목" 참고
2. **② 야간·심야 시간대:** 담당자가 고른 요일·시각(예: 평일 20시, 22시. 토·일·공휴일 구분 포함)에 문을 연 기관만 남기고 다시 계산
   - 약국은 국립중앙의료원 API의 전체 약국 운영시간을 반영하고, 공공심야약국은 구분해 표시(공공심야약국만 남기면 20시처럼 일반 약국도 여는 시각의 공백이 실제보다 크게 나옴)
   - 운영시간 자료를 쓸 수 없거나 품질이 나쁘면, 시각 선택을 심야(예: 22시 이후)로 한정하고 그 가정을 화면에 표시
   - 공공심야약국의 공식 지정 시간과 API 운영시간이 다르면 공식 자료를 우선하고 차이를 기록
   - 야간진료 기관(2순위)에도 같은 원칙(운영시간 자료로 판단하고 공식 지정 기관은 구분 표시)을 적용하되, 의원 운영시간 자료의 품질을 확인해 설계서에서 확정
   - 약국의 기준 목록은 1차 분석의 인허가 목록(영업 중 101곳)으로 하고, 국립중앙의료원 API 운영시간을 붙이는 연결 규칙(예: 도로명주소 → 전화번호 → 이름 순)을 설계서에서 정할 것. 규칙으로 연결되지 않은 건은 정제 보조(구현 범위 7)로 처리
   - 연결되지 않았거나 고른 요일·시각의 운영시간이 없는 시설은 "운영시간 미확인"으로 따로 표시(기획안 ②). 계산에서 닫힘·열림 중 무엇으로 볼지는 "미정 항목" 참고
3. **③ 기준 설정:** 국가적 최저기준(국가도시재생기본방침. 예: 어린이집 도보 5분, 초등학교·근린공원 도보 10~15분, 10만㎡ 이상 거점공원 차량 10분)을 기본값으로 둠
   - 범위로 된 기준(10~15분 등)은 어느 값을 기본값으로 할지 규칙을 정할 것. 참고: 국토교통부 「지역의 기초생활인프라 공급 현황 자료 및 분석 안내서」(2019)는 기준이 범위면 높은 값을 적용함(원문 확인 후 기본안으로 검토)
   - 의원·약국은 국가적 최저기준이 시간값을 정하지 않고 지역 보건의료 수요를 고려해 지자체가 정하도록 맡긴 항목이므로(현행 원문으로 확인), 담당자가 "도보 N분"처럼 입력하면 기준 초과 인구를 집계. 초기값은 "미정 항목"에 따르고, 화면에는 "국가 기준상 지자체가 정하는 항목, 담당자 설정값"으로 표시. 발표에서 이 기능을 '국가 기준이 지자체에 맡긴 값을 양주시가 정하도록 돕는 도구'로 설명할 수 있게 근거를 정리
   - 학교는 국가 기준이 초등학교에만 있으므로 대상 학교급과 기준을 설계서에서 제안
   - 차량 시간이 아직 없으면 도보 기준만 기본값으로 표시
4. **④ 후보 비교:** 지도에서 심야약국·야간진료 후보지를 찍으면, 담당자가 고른 요일·시각 기준(후보는 그때 문을 연다고 가정)으로 기준을 새로 충족하는 인구를 계산해 후보끼리 비교. 공공병원 후보는 차량 시간 기준으로 비교하되, 비교 기준이 되는 기존 시설군(예: 응급실 운영 의료기관, 국가 기준 차량 30분)과 기준값을 설계서에서 제안(차량 시간과 함께 3순위)
5. **자연어 질의:** "옥정에 심야약국을 두면 몇 명이 해소되나?"(기획안 예시 문장) 같은 질문을 LLM이 버튼형 질의와 같은 형식의 조건(JSON)으로 바꾸면, 브라우저가 그 조건으로 분석 함수를 실행하고 답변 문장은 화면 템플릿으로 만듦. 최종 판단은 담당자
   - 조건 항목: 시설, 요일·시각, 이동수단(일반 보행·느린 보행·차량), 기준(N분), 후보 위치, 집계 지역(행정동)
   - LLM은 질문에 들어 있는 조건값만 옮기고, 분석 결과 숫자(인구 등)를 만들거나 답변 문장을 쓰지 않음(보고서 초안은 구현 범위 6 참고). 질문 1건당 LLM 호출은 1회
   - 지명을 행정동이나 지점으로 바꾸는 규칙(예: 행정동 대표점, 지도에 미리 찍어 둔 후보)을 설계서에서 제안. 기본안: "옥정"처럼 행정동 두 곳에 걸치는 지명은 해당 행정동 모두(옥정1·2동)로 보고, 지명만 있고 지점이 없으면 그 지역에 미리 찍어 둔 후보를 모두 비교해 답함(되묻기 없이). 기획안 예시 문장을 시연에서 그대로 쓸 수 있게 할 것. 그 지역에 미리 찍어 둔 후보가 없으면 행정동 대표점을 후보로 계산하고, 답에 그 사실을 밝힘
   - 빠진 조건은 현재 화면 설정값으로 채우고 답에 사용한 값을 밝힐 것. 위치처럼 기본값으로 채울 수 없는 조건이 빠졌을 때(지명도 지점도 없을 때)만 다시 질문
   - 1순위 범위는 약국·심야 질문으로 한정하고, 다른 시설은 2순위에서 같은 조건 형식으로 넓힘
6. **보고서 초안(기획안 'AI 활용 방안'):** 분석 결과(함수 출력)로 현황, 후보별 변화, 자료 기준일과 가정을 설명하는 보고서 초안. 최종 판단은 담당자
   - LLM은 숫자를 직접 쓰지 않고, 결과·조건 항목을 가리키는 자리표시자(예: {추가_수혜_인구}, {시각}, {기준_분})로 문장만 만듦. 숫자는 브라우저가 함수 결과와 조건으로 채움
   - 검사: 출력에서 자리표시자와 허용 목록(행정동 이름처럼 숫자가 들어간 고유명사)을 뺀 뒤 숫자가 남거나, 결과에 없는 자리표시자가 있으면 버리고 템플릿 보고서로 대체. 출처·기준일·가정 문단은 템플릿으로 고정
   - 비교·증감 표현: LLM에는 숫자 대신 결과의 방향(후보 간 순위, 증감 부호, 기준 충족 여부)만 입력으로 주고, 출력 문장의 비교·증감 표현이 이 값과 맞는지 검사. 맞지 않거나 검사할 수 없으면 템플릿 보고서로 대체. 검사 규칙을 만들기 어려우면 비교 문장은 템플릿으로 고정하고 LLM은 설명 문장만 쓰게 할 것
   - LLM 호출은 보고서 버튼을 누를 때만 1회. 템플릿 보고서는 LLM 없이도 동작
   - 템플릿 보고서(현황·후보별 변화·자료 기준일·가정을 함수 결과로 채움)는 1순위, LLM 문장은 2순위. LLM 문장을 못 만들어도 기획안의 보고서 초안 약속은 템플릿으로 지킴
7. **정제 보조(기획안 'AI 활용 방안'):** 시설 목록끼리 연결할 때(약국 인허가 목록과 국립중앙의료원 API, 의원 목록과 심평원 진료과목 자료 등) 규칙으로 연결되지 않은 건만 LLM이 연결 후보와 근거를 내고 팀이 확정
   - 데이터 준비 단계(로컬)에서만 쓰고 배포 화면에서는 쓰지 않음. LLM에는 공개된 시설 정보(이름·주소·전화번호)만 보냄. 연결 표(후보·확정 여부·근거)는 원본 저장소에 남기고 AI_LOG.md에 기록. 정제 보조는 중계 함수를 거치지 않음. 기본은 공모전에서 팀별로 제공한 Claude 계정으로 수행(API 키 불필요, 대화 기록을 AI_LOG.md에 옮김). API로 돌릴 경우에만 보안·개인정보 절의 키 분리 규칙을 따름.

- 국토지리정보원 국토조사가 250m·500m 격자로 생활인프라 접근성 통계를 만들어 왔으므로, 격자 크기만을 차별점으로 내세우지 말 것. 차별점은 야간 운영시간 반영, 후보 비교, 느린 보행, 자연어 질의(담당자가 직접 묻는 방식)에 둘 것. 비교 대상에는 도시재생종합정보체계(city.go.kr) '우리동네 재생정보'(국가최저기준 미달지역 판단 자료)와 다른 지자체의 격자 접근성 데이터(예: 충청북도 200m 격자 생활인프라 접근성, 2025.12)도 넣어 실제 제공 범위를 확인하고 차별점 표를 만들 것. 기획안의 '기존 도구는 시군구 단위' 표현은 발표에서 쓰지 말 것

## 검증
- 격자 인구 합계를 행정동 인구(양주시 298,139명, 2026년 9월)와 비교하고, 기준연도 차이(격자 인구 최신본은 2024년 기준), 인구 정의 차이(주민등록 인구와 총조사 기반 격자 인구의 외국인 포함 여부 등), 원자료의 비밀보호(노이즈, N/A)를 포함해 차이의 원인을 보고할 것(억지로 맞추지 말고, 보정이 필요하면 방법을 제안할 것). 옥정처럼 인구가 빠르게 늘어난 지역은 따로 볼 것
- 시연·발표에 쓸 숫자를 보정 전·후 중 무엇으로 할지 제안할 것
- 행정동별 시설 수가 access-report.html의 1차 분석과 일치하는지 확인하고, 다르면 차이와 원인(수집 시점 등)을 보고할 것
- 공공심야약국의 공식 지정 시간과 API 운영시간이 다른 경우를 목록으로 남기고, 시 공지의 야간시간대 운영 약국 안내와도 비교할 것. 지정 시간(21~24시)과 약국 자체 영업시간이 따로 안내된 경우도 넣을 것(예: 선암건강약국은 2025.2 보도에서 영업시간을 10~24시로 안내했다고 함, 확인 필요)
- 약국 기준 목록과 API 운영시간의 연결 결과(규칙으로 연결된 수, 정제 보조로 확정한 수, 미확인 수)를 보고할 것
- "옥정1동 약국 공백"은 동 안 시설 수에서 나온 가설이므로, 이동시간 기준(옆 옥정2동 약국 포함)과 시연 시각 기준으로도 공백이 나타나는지 사전 실험에서 먼저 확인하고, 결과로 시연 지역·시각을 정할 것

## 구현 원칙
- 배포는 GitHub Pages(정적 파일만 가능). LLM 중계 함수 외에는 별도 서버 없이 동작하도록 설계
- 저장소는 두 개로 나누고, 원본 저장소의 배포용 폴더(예: site/)만 배포 저장소로 옮기는 방법을 마련(수동 복사 또는 GitHub Actions)
- 수집 → 정제 → 사전 계산 → 배포 파일 생성을 명령 하나로 다시 돌리는 갱신 스크립트를 둘 것. 기획안의 '자동 갱신 구조'는 이 재실행 갱신으로 구현하고, 자료 기준일이 배포 파일과 화면에 함께 바뀌게 할 것

- 서비스 첫 화면은 index.html. access-report.html은 내용을 그대로 두되 noindex 메타 추가, '통계청' 표기 2곳을 '국가데이터처'로 수정, 글꼴을 로컬 파일로 연결하는 것, 하단 출처 영역에 수정 표시 한 줄을 넣는 것만 허용(지금 화면에 보이는 Noto Sans KR을 로컬로 넣어 모양을 유지할지, 새 화면과 같은 글꼴로 바꿀지 설계서에서 정함). 고친 뒤에는 리포트 하단 출처 영역에 수정일과 수정 내용(기관명 표기, noindex, 글꼴)을 한 줄로 표시. 첫 화면에서 1차 분석 리포트로 연결할 것
- 격자·시설별 이동시간은 도로망 그래프에서 시설을 출발점으로 한 최단경로로 미리 계산해 JSON/GeoJSON 등 파일로 배포(차량은 일방통행 때문에 방향에 따라 시간이 달라지므로, 격자에서 시설로 가는 시간이 되게 계산). 도보는 시간 대신 거리(m)로 저장하고 속도(일반·느린 보행·설정값)로 나눠 시간을 구할 것. ②의 재계산을 위해 격자마다 가장 가까운 1곳이 아니라 제한 거리 안의 시설 전부(또는 가까운 K곳)를 저장하고, 제한 거리와 K는 설정값으로 둘 것
- 요일·시각별 재계산(②)과 기준(N분)별 인구 합산(③)은 미리 계산한 이동시간으로 브라우저에서 할 것
- 후보 비교는 브라우저에서 계산(미리 만든 도로망 그래프 파일 사용)
- 화면에서 쓰는 LLM 연동은 Cloudflare Workers 등 무료 서버리스로 분리한 중계 함수 1개로 처리(정제 보조는 구현 범위 7 참고). 중계 함수는 질문을 조건(JSON)으로 바꾸는 일과 보고서 초안 문장(자리표시자만, 구현 범위 6)을 만드는 일만 함
- 일반 보행 속도와 도로 종류별 차량 속도는 근거 자료와 함께 설계서에 제안하고, 설정값으로 둘 것(일반 보행 속도는 "미정 항목" 참고. 차량 참고: 국가 기준 충족도를 분석한 선행연구는 지역거점시설에 평균 25km/h를 적용)
- 로그인·권한 관리는 만들지 않음. 담당자 화면과 시민 화면은 메뉴로만 구분(실제 도입 때 시청 내부망·인증 적용은 발표에서 계획으로 설명)
- 화면은 2D 지도. 디자인은 access-report.html의 색·글꼴·구성을 따를 것
- 시민 화면은 휴대폰에서도 쓸 수 있게 만들 것
- 개발 기간이 짧으니 단순한 구조를 우선

## 보안·개인정보
- 배포 저장소에는 배포용 폴더의 파일만 올리고, API 키, .env, 멘토링 자료, 원본 데이터, 수집·계산 코드는 절대 넣지 말 것. 여기서 원본 데이터는 기관에서 내려받은 원자료와 API 응답을 그대로 저장한 파일을 말하며, 배포에는 화면과 브라우저 계산에 필요한 가공 파일만 넣을 것
- 브라우저에서 실행되는 화면 코드와 결과 파일은 누구나 볼 수 있으므로, 숨겨야 할 정보(프롬프트, 키, 원본 데이터)는 그 안에 두지 말 것
- API 키(SGIS, 국립중앙의료원, LLM 등)는 절대 화면 코드에 넣지 말 것. 데이터 수집용 키와, 정제 보조(구현 범위 7)를 API로 돌릴 경우의 LLM 키는 로컬 .env(.gitignore 등록), 화면에서 쓰는 LLM 키는 서버리스 중계 함수의 환경 변수에만 저장. 이 경우 두 LLM 키는 따로 발급하거나 한도를 나눠, 정제 보조가 시연용 사용량을 쓰지 않게 할 것. 배경지도처럼 브라우저에서 쓰도록 만들어지고 도메인으로 제한되는 키를 허용할지는 "미정 항목"에서 정함
- 중계 함수는 허용 목록에 있는 주소(우리 GitHub Pages 주소, 로컬 실행 주소)에서 온 요청만 받을 것. 단, 이 확인은 브라우저 밖에서 위조할 수 있고 로컬 실행 주소를 허용하면 누구나 자기 컴퓨터에서 호출할 수 있으므로 보조 수단으로 보고, 실제 방어는 호출 횟수 제한과 하루 한도로 할 것. 허용 목록과 한도는 설정값으로 둘 것
- LLM 출력은 정해진 조건 형식(JSON)만 허용하고, 브라우저는 형식 검사를 통과한 조건으로 분석 함수만 실행할 것. 보고서 초안은 숫자를 자리표시자로만 쓰게 하고, 행정동 이름 등 허용 목록 밖의 숫자가 있으면 버림
- 인구가 적은 격자의 처리 방식과 기준은 "미정 항목" 참고. 브라우저 계산용 격자 인구는 배포 파일에 들어가므로 화면에서 가린 값도 파일에서는 보이고, 두 후보 결과의 차이로 작은 격자의 값을 역산할 수 있다는 점을 전제로 설계할 것. 원자료에 이미 적용된 비밀보호(노이즈, N/A)를 확인해 반영할 것
- 시민 화면의 위치 정보는 서버에 저장하지 않고 브라우저에서만 처리
- 검색엔진 수집 차단(noindex) 적용. GitHub Pages는 응답 헤더를 바꿀 수 없으므로 모든 HTML(access-report.html 포함)에 meta 태그로 넣고, 공개 저장소 자체는 검색될 수 있음을 전제로 둘 것

## 비용
- **비용 0원이 원칙.** 결제 수단을 등록하지 않고 쓸 수 있는 무료 사용량 안에서만 동작하게 설계할 것
- 무료 사용량을 넘으면 요금이 나가는 대신 호출이 멈추는 구조여야 함
- 응답 길이 제한, 호출 횟수 제한, 하루 사용 한도를 두고, 한도를 넘거나 LLM이 응답하지 않으면 예시 질문 결과 화면과 버튼형 질의(시설·요일·시각·이동수단·기준·후보·집계 지역 선택)로 대체할 것. 보고서 초안은 템플릿 보고서로 대체
- 질문 1건당 LLM 호출은 1회(질문을 조건으로 바꾸는 일)로 설계해 사용량을 줄일 것. 보고서 초안은 버튼을 누를 때만 1회 추가
- 본선 당일 다른 사용자가 무료 한도를 먼저 써 버리지 않도록, 시연용 사용량을 따로 남기는 방법을 설계서에서 제안할 것
- LLM이 없어도 지도·기준 설정·후보 비교·버튼형 질의·템플릿 보고서는 모두 동작해야 함

## 현장 시연 대비
- 본선은 오프라인 현장 발표. 노트북에서 로컬로 실행하는 방법을 README에 넣을 것. index.html을 파일로 직접 열면 브라우저가 JSON 파일을 읽지 못하므로, 로컬 서버로 여는 방법을 적을 것. PMTiles를 쓰면 Range 요청을 지원하는 로컬 서버(예: npm http-server)로 여는 방법을 기준으로 적을 것
- 인터넷 없이도 격자 지도와 분석이 동작하도록, 배경지도 없이 행정동 경계만 그리는 오프라인 모드를 둘 것. 지도 라이브러리·글꼴 등 외부 파일은 CDN에 의존하지 말고 모두 로컬에 포함하고, 오프라인 모드의 질의는 버튼형으로 동작
- LLM 질의가 실패하면 비용 섹션의 대체 화면(예시 질문 결과, 버튼형 질의)으로 넘어갈 것. 예시 질문 결과는 실제로 계산한 결과임을 표시
- 시연 질문 문장은 미리 정해 예시 질문 목록에 넣을 것(LLM이 실패해도 같은 결과를 보여 줄 수 있게). 기획안 예시 문장("옥정에 심야약국을 두면 몇 명이 해소되나?")을 쓰면 자연어 질의의 지명 규칙(구현 범위 5)으로 되묻기 없이 처리되는지 확인할 것
- 시연 시각은 공공심야약국 운영시간(매일 21~24시) 안에서 고르고(예: 평일 22시), 사전 실험에서 공백이 확인된 지역으로 시연할 것
