# 앱 마스킹 구현 안내서 (앱 담당용)

사진의 얼굴과 차량 번호판을 **휴대폰 안에서 먼저 가린 뒤** 가린 사진만 서버로 보내기 위한 구현 기준입니다. 앱은 AI 판독 모듈을 직접 부르지 않고 업무 백엔드 API로 사진을 올립니다. 백엔드가 그 사진을 AI로 넘깁니다. **"서버에는 가린 사진만 들어온다"는 원칙은 앱 마스킹이 지킵니다.** 서버는 받은 사진을 저장하기 전에 가림 상태를 한 번 더 확인하고, 혹시 남은 부분이 있으면 저장·AI 판독 전에 가립니다. 이 확인은 놓친 것이 저장소·외부 AI·담당자 화면으로 퍼지지 않게 막는 안전망이고, 서버가 가린 수(`server_added`)는 앱 마스킹 성능을 재는 기록이 됩니다. 0이 정상입니다.

## 1. 촬영부터 전송까지

1. **앱 안 카메라로만 찍습니다.** 휴대폰 갤러리(사진첩)에 저장하지 않습니다.
2. **방향을 바로잡습니다.** 찍은 사진의 회전 정보(EXIF Orientation)를 픽셀에 반영합니다. 검출기는 똑바로 선 사진에서 얼굴을 훨씬 잘 찾습니다.
3. **얼굴·번호판·차량을 찾습니다.** 찍은 원본 해상도에서 찾습니다(2장 참고). 너무 크면 긴 변 2,400px까지 줄여서 찾고, 좌표는 원본 크기로 되돌립니다.
4. **가립니다** (3장 참고).
5. **긴 변 1,568px로 줄입니다.** 메타데이터(GPS·기기 정보)를 넣지 않은 JPEG로 다시 저장합니다. 위치는 사진 파일이 아니라 업무 API의 위치 필드로 따로 보냅니다.
6. **원본을 지웁니다.** 메모리와 임시 파일 모두에서 지웁니다. 기기에 남겨도 되는 것은 가린 사진뿐입니다.
7. **업무 백엔드로 전송합니다** (4장 참고). 통신이 안 되면 가린 사진을 기기에 보관했다가 다시 보내는 방식은 업무 백엔드 API 명세의 오프라인 계약을 따릅니다.

**실패하면 보내지 않습니다.** 검출이나 가림 중 오류가 나면 사진을 보내지 말고 지운 뒤 "한 번 더 찍어 주세요"를 띄웁니다. 가리지 못한 사진이 전송되는 경로가 없어야 합니다.

## 2. 검출 도구

| 대상 | 안드로이드 | 아이폰 |
|---|---|---|
| 얼굴 | Google ML Kit Face Detection (`PERFORMANCE_MODE_ACCURATE`, 작은 얼굴 최소 크기 낮게) | Apple Vision `VNDetectFaceRectanglesRequest` |
| 번호판 (임시) | ML Kit Text Recognition v2 한국어 인식 + 번호판 패턴 | Vision `VNRecognizeTextRequest`, 인식 언어 `ko-KR` (iOS 16 이상) |
| 번호판 (최종) | 서버와 같은 사전 학습 번호판 모델(ONNX). ONNX Runtime Mobile로 그대로 돌리거나 TFLite로 변환 | 같은 모델을 ONNX Runtime Mobile로 돌리거나 CoreML로 변환 |
| 차량 (안전망) | MediaPipe Object Detector (COCO 사전 학습 EfficientDet-Lite0) | 같은 MediaPipe Object Detector 또는 Vision 물체 인식 |

**번호판 임시 방식:** 학습 모델이 나오기 전까지는 글자 인식으로 번호판을 찾습니다. 아래 둘 중 하나라도 맞는 글자 영역은 번호판으로 보고 가립니다.
- 정규식 `\d{2,3}\s*[가-힣]\s*\d{4}`에 맞는 글자 줄 (예: `12가3456`, `123가 4567`, `서울12가3456`의 일부)
- 숫자 4개가 연속하고 한글이 한 글자 이상 섞인, 5~10자짜리 짧은 글자 줄 (멀리서 일부만 읽힌 번호판)

**차량 안전망:** 자동차·버스·트럭·오토바이를 찾았는데 그 안에서 번호판을 하나도 못 찾았으면, 차량 전체를 얼굴과 같은 방식으로 거칠게 뭉갭니다. 번호판 검출이 놓쳐도 번호가 남지 않게 하는 장치로, 서버도 같은 규칙을 씁니다. 점검 사진에서 차량은 배경이라 가려도 판독에 지장이 적습니다.

글자 인식은 비스듬하거나 먼 번호판을 놓칠 수 있습니다. 놓친 것은 서버가 2차로 잡도록 되어 있지만, 학습 모델로 바꾸기 전까지는 서버 기록의 `server_added`를 매주 확인해 주세요.

각 도구의 최신 사용법과 지원 언어는 공식 문서에서 다시 확인하세요.

## 3. 가리는 방법

| 대상 | 방법 | 상자 확장 |
|---|---|---|
| 얼굴 | 가로 6칸 정도로 아주 거칠게 모자이크한 뒤 흐림 | 사방 25% |
| 번호판 | 회색(#3C3C3C) 단색으로 덮기 | 사방 20% |
| 번호판을 못 찾은 차량 | 얼굴과 같은 거친 모자이크 + 흐림 | 사방 5% |

약한 흐림이나 잘게 나눈 모자이크는 복원 시도가 가능합니다. 서버와 같은 방식으로 맞춰 주세요(`privacy.py`의 `_pixelate`, `PLATE_FILL`).

## 4. 전송 형식

사진은 업무 백엔드의 사진 제출 API로 올립니다. 경로와 전체 필드는 업무 백엔드 API 명세를 따르고, 마스킹과 관련해 꼭 채울 값은 아래와 같습니다.

| 업무 API 필드 | 값 |
|---|---|
| `deviceMasked` | `true` (앱에서 가렸음) |
| `deviceMaskReport` | `{"faces": 1, "plates": 0, "vehicles": 1, "detector": "mlkit+ocr+plate+vehicle", "appVersion": "1.0.0"}` |
| `maskingVersion` | 앱 마스킹 규칙의 버전 (검출 도구나 가리는 방법을 바꾸면 올림) |
| `capturedAt` | 촬영 시각, ISO 8601 |

백엔드는 이 값을 AI 형식(`device_masked`, `device_mask_report`, `app_version`은 snake_case)으로 바꿔 넘깁니다. AI는 운영 설정(`REQUIRE_DEVICE_MASKING=1`)에서 `deviceMasked`가 없는 사진을 받지 않습니다.

AI는 저장 전 확인에서 앱이 놓친 부분을 가린 수(`server_added`)를 기록합니다. 0이 정상이고, 0이 아니면 앱이 놓친 것입니다. 이 값은 앱 화면에는 오지 않으며, 백엔드가 주 단위로 모아 공유하면 앱 검출기를 보완하는 데 씁니다.

## 5. 성능 목표와 시험

- **처리 시간:** 저사양 휴대폰 기준으로 촬영 후 전송까지 3초 이내. 시범 참여자가 실제로 쓰는 기종 2~3종에서 직접 재 주세요.
- **가림 성공률:** AI 담당이 만드는 라벨 사진 300장(얼굴·번호판 위치 표시)으로 시험합니다. 목표는 얼굴·번호판 각각 98% 이상입니다.
- **배터리:** 하루 순회(사진 100장 안팎)에서 앱 사용으로 줄어드는 배터리량을 기록합니다.

## 6. 그 밖의 요구사항

- **촬영 사실 표시:** 촬영음을 끄지 않습니다. 업무 목적으로 공개된 장소에서 촬영하므로, 촬영 사실을 알릴 방법(조끼·명찰 표시와 함께)이 필요합니다.
- **위치 기록 최소화:** 촬영할 때의 위치만 보냅니다. 이동 경로를 계속 기록하지 않습니다.
- **번호판 모델:** AI 담당이 서버와 같은 사전 학습 번호판 모델 파일과 입출력 형식을 넘깁니다. 앱은 글자 인식 방식과 함께 돌려서, 둘 중 하나라도 찾은 곳을 가립니다. 실제 사진 평가 후 추가 학습본이 나오면 같은 방식으로 교체합니다.

## 7. 앱 화면에서 할 일

- **앱 안 카메라로만 찍습니다.** 갤러리에서 사진을 고르는 기능을 두지 않습니다. 원본이 갤러리에 남지 않게 하기 위해서입니다.
- **수리 확인·재점검 촬영 화면에서 이전 사진을 반투명하게 겹쳐 보여 줍니다.** 같은 위치·각도로 찍혀야 AI의 전후 비교가 정확해집니다. 겹쳐 볼 사진은 업무 백엔드가 내려주는 승인된 가린 사진만 쓰고, 받을 수 없으면 겹쳐 보기 없이 찍습니다.
- **어르신 화면에는 판독 결과를 띄우지 않습니다.** 위험도·이상 여부·판독 근거는 담당자 화면에만 있고, 어르신 화면에는 업무 백엔드가 내려주는 재촬영·진행 안내만 표시합니다.
