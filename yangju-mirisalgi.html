01

문제 정의

싼 동네의 숨은 비용, 그리고 시가 보지 못하는 이사 고민층

시민의 문제

집값만 보고 고르면 1년이 안 보인다

  • 월세가 싼 대신 출퇴근이 길면 교통비와 시간이 늘어난다
  • 장보기·병원·운동시설이 멀면 생활 이동시간이 쌓인다
  • 지역마다 받을 수 있는 지원(교통비 환급, 청년 지원)이 다르다
  • 정보는 곳곳에 흩어져 있고 서로 합산되지 않는다 — “월 20만 원 아끼고 한 달 8시간 더 쓰는 게 이득인가?”에 답해주는 곳이 없다

양주시의 문제

고민하다 떠난 사람은 보이지 않는다

  • 시는 전입 신고한 사람은 알지만, 양주를 고민하다 다른 곳을 고른 사람이 무엇 때문에 포기했는지는 알 수 없다
  • 청년 지원·교통비 환급 같은 정책이 이사를 판단하는 시점에 노출되지 않는다
  • 이사의 가장 큰 이유는 주거인데, 판단은 대부분 집값 위주로 이뤄진다

계산 엔진 — 근거 등급

데이터가 없는 차이는 지어내지 않는다

① 지역 차이는 데이터로

주거비·출퇴근·시설 거리처럼 지역 차이를 만드는 항목은 실제 데이터로 계산.

② 개인 차이는 입력으로

운동비·반려동물·통신비처럼 사람마다 다른 항목은 사용자에게 받는다.

③ 없으면 빼고, 뺐다고 표시

데이터가 없는 항목은 추정치로 채우지 않고 비교에서 제외한다.

항목별 계산식

모든 수치는 LLM이 아닌 계산 엔진에서 나온다

월 주거비 실측

월세형 = 월세 + 보증금 × 기회비용 이율 ÷ 12 + 관리비
전세형 = 전세보증금 × 전세대출 금리 ÷ 12 + 관리비
  • 생활권(법정동 묶음)별 최근 12개월 실거래 중 가구형태에 맞는 면적 구간의 중위값 사용
  • 거래 건수를 함께 표시해 표본이 적은 생활권을 알림

월 교통비 실측 정책

대중교통 = 월 출근일수 × 왕복 요금 − 교통비 환급액
자차 = 유류비 + 보험·주차 등 고정비
  • 왕복 요금은 경로 API의 실제 요금
  • 환급액은 K-패스·The 경기패스 규칙(거주지·연령·월 이용횟수)으로 계산, 기준일을 화면에 표시

이동시간 실측

출퇴근 = 월 출근일수 × 왕복 소요시간(출근 시간대)
생활 이동 = Σ (우선순위 시설 월 이용 횟수 × 왕복 접근시간)
  • 생활권마다 대표 지점 3곳, 가장 가까운 시설까지 도보(시속 4km) 또는 대중교통 시간
  • 생활편의는 점수 대신 “마트 도보 8분”처럼 분 단위로

잔여소득과 1년 환산

잔여소득 = 월소득 − (주거비 + 교통비 + 공통 생활비 + 입력 지출) + 정책 지원액
1년 저축 가능액 = 잔여소득 × 12
1년 이동시간 = (출퇴근 + 생활 이동) × 12 → “약 ○일”

AI의 역할과 안전장치

AI는 말을 이해하고 설명한다. 숫자는 만들지 않는다.

생활 프로필 구조화
자연어 설명 → 프로필 데이터. 빠진 항목은 되묻기.
우선순위 해석
“돈 아끼고 싶지만 출퇴근 길면 싫어요” → 주거비·출퇴근 민감도 가중치.
What-if 해석
“차 사면 어때요?” → 시나리오와 바꿀 변수.
결과 설명
엔진 출력값 → 3문장 이내 설명 + 근거 등급·출처.
정책 자격 설명
룰 판정 결과 → 쉬운 말 설명, 필요한 서류·신청처 안내.

프로필 데이터 예시 (페르소나 A)

{ "monthly_income": 2800000, "household": "1인", "car": false, "pets": ["반려견"], "commute": { "destination": "서울 강남구 삼성동", "days_per_week": 5 }, "rent_budget": 700000, "priorities": ["운동시설", "동물병원", "마트"], "sensitivity": { "housing_cost": "높음", "commute_time": "높음" } }

안전장치

  • LLM은 숫자를 만들지 않는다 — 모든 수치는 계산 엔진에서만
  • 설명문 속 숫자를 엔진 출력과 자동 대조, 다르면 다시 생성
  • 정책·시설은 DB에 등록된 항목만 언급하고 출처 표기
  • 판정이 불확실하면 단정하지 않고 “확인 필요”

소득·가구·반려동물 같은 생활 정보를 다루므로 처음부터 최소 수집

저장하지 않음

개인 프로필은 계산에만 쓰고 세션이 끝나면 삭제.

집계는 구간으로

소득은 100만 원 구간, 나이는 연령대, 가구는 유형만. 자연어 원문은 저장하지 않음.

위치는 행정동까지

출퇴근지는 좌표 대신 행정동 단위로만 저장.

외부 전송 전 가림

외부 LLM으로 보내기 전 이름·연락처·상세주소 마스킹.

동의 기반

집계 저장은 사용자가 동의한 경우에만.

소표본 비공개

10건 미만 집계는 행정 화면에 표시하지 않음 (재식별 방지).

이 원칙은 멘토링(장웅태 멘토)에서 검토받습니다.
